# v1.2 Planning & Backlog — locked decisions (2026-07-24)

Consolidated from the clarification dialog. This is the working spec for the next release.

## Versioning & patch-notes process

- **v1.0.0 = Launch Tournament (late June 2026).** Everything before = Beta (0.x).
- **Current live = v1.1.** Post-launch batch (BaLi 2.0, Faction War, Majors, quick-wins, …).
- **Next = v1.2** — bundle *everything that is ready* into one release; split into finer minors later.
- **Scheme (SemVer, web-app-adapted):**
  - Fix (broken behaviour) → **Patch** (1.1.x), patch-notes section **🔧 Fixes**.
  - Update (new/improved capability) → **Minor** (1.x.0), section **✨ New / ⚙️ Improvements**.
  - New pillar (e.g. Conquest/land-battle) → **Major** (2.0).
  - Maps to commit convention: `fix:` → Fixes, `feat:` → New/Improvements.
- **Process:** `CHANGELOG.md` in Keep-a-Changelog format with an `[Unreleased]` collector block, moved under `## [1.2.0] – date` at release; git-tag `v1.2.0`; Claude drafts Discord patch notes each release in two voices (technical + grimdark).

| #12 | "Catch-up · 0 pts" badge shown on a checked-in-at-start player's round-1 slot | **Real bug — it's a FRONTEND display bug, no scoring penalty ever applied.** `MatchNode.tsx:129` sets `isCatchupBye = CATCHUP_BYE \|\| PENDING_BYE`, and line 224 renders the badge **"Catch-up · 0 pts"** for both. But a `PENDING_BYE` is a normal *provisional* bye from the commit-when-free engine — ANY checked-in player can get one when their optimal partner isn't free yet; it later crystallises into a **scored** BYE (full points, if `late_joined=false`) or is reclaimed into a real match. BossToss was checked in long before start (`late_joined=false`), got a provisional PENDING_BYE in R1, the UI mislabelled it "Catch-up · 0 pts", then it was reclaimed into the real match vs TL and he won all 4 (final score 4). The badge lied; he was never penalised. **Fix:** distinguish the two in the UI — a neutral "provisional / awaiting opponent" label (NO "0 pts") for `PENDING_BYE`; keep "Catch-up · 0 pts" only for a real `CATCHUP_BYE`. (Separately, the late-join/force-checkin catch-up mechanics from the earlier analysis are their own topic, tied to #11.2 + the start-check-in guard — but they are NOT what BossToss hit.) |
